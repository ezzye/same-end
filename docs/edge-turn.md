The owner selected the current Mac as the edge host. Its private coturn runtime, capacity agent and prerequisite supervisor are installed as user LaunchAgents. Router verification is currently failing, so cloud TURN URLs remain empty and new edge credentials are disabled. No cloud media relay is used. Keep TURN and health-signing secrets separate, independently generated and in protected secret storage; never commit either to the app, client bundle, sample config, or logs. On a new installation, the CloudFormation defaults leave URLs and secrets empty and capacity limits at zero until the operator prepares and verifies that host.

## How it fits

The coordinator issues short-lived, expiring TURN REST credentials only when an operator has configured the edge URLs and shared secret and a fresh edge-health report says `healthy`. The contract is `createEdgeTurnCredentials({urls, secret, nowMs, ttlSeconds})`, returning `{iceServers, expiresAt}`. With no URLs or secret it returns an empty `iceServers` list. Usernames contain an expiry timestamp and random nonce; the credential is HMAC-SHA1 over that username, encoded as base64, as coturn's TURN REST authentication expects. TTL is limited to 60–3600 seconds. TURN URLs must use `turn:` or `turns:` with a host and cannot contain username/password authentication.

The edge agent sends only allowlisted host measurements and state metadata to `POST /v1/edge-health`; it never sends media, user identity, room identifiers, TURN credentials, or coturn secrets. The signature is HMAC-SHA256 in lowercase hex over the exact UTF-8 body bytes prefixed by `<x-edge-timestamp>.`. The timestamp is Unix milliseconds, must equal the JSON `sampledAtMs`, and must be fresh. The coordinator persists the latest report with conditional writes and rejects a timestamp that does not advance. The report expires after `reportTtlMs` (15 seconds by default).

A report is `healthy` only when CPU, available memory, outbound rate, coturn allocation count, and administrator-declared uplink and allocation budgets are all known and within configured headroom. A known threshold breach is `constrained`; missing required readings or an unconfigured capacity budget is `unknown`; an expired report is `stale`. All states except `healthy` deny new ICE credentials/admission. Existing allocations are not terminated. A previously issued credential may remain valid until expiry and can potentially be reused, so coordinator admission gating alone does not guarantee that no new allocation is made during that window.

## Continuous host agent

`edge-turn/config.example.json` is a template. Copy it to a private operator-managed location, select actual budget values from measured or declared provider capacity, and set `reportUrl` only after the coordinator endpoint is deployed. Set `EDGE_TURN_HEALTH_SECRET` in the agent's protected environment; it must match the coordinator's `EDGE_TURN_HEALTH_SECRET`. The config contains no secret by design. For a remote heartbeat, require `reportUrl` to be the coordinator's deployed HTTPS health endpoint, a loopback `metricsUrl`, `uplinkBudgetMbps` greater than zero, a positive safe-integer `allocationLimit`, and a distinct `EDGE_TURN_HEALTH_SECRET` of at least 24 characters. The agent rejects missing minimum remote configuration and invalid headroom ratios. `reportTtlMs` must exceed `intervalMs` by more than five seconds. Supply coturn's separate TURN REST shared secret using a protected runtime config/database mechanism; coturn does not expand arbitrary environment variables in its sample config.

Use Node.js 20 or later. The agent has no install step and takes no action without an explicit config path:

```sh
node edge-turn/agent.mjs --selftest
node edge-turn/agent.mjs --config /secure/path/edge-turn.json --once --dry-run
node edge-turn/agent.mjs --config /secure/path/edge-turn.json --serve
```

`--selftest` is local and network-free. `--once --dry-run` samples once and prints a bounded report without sending it. `--serve` remains in the foreground and samples in a serial loop at the configured interval (1–60 seconds), so slow samples cannot overlap. It provides an allowlisted local-only `GET /health` endpoint bound to `127.0.0.1` and posts a fresh signed heartbeat each cycle when `reportUrl` is set. In that mode the endpoint reflects the coordinator's validated health acknowledgement, not just the agent's local estimate; without a report URL/acknowledgement it returns `unknown` and `allowNew:false`. Redirects are rejected for both report and metrics requests. Configure `reportUrl` and `EDGE_TURN_HEALTH_SECRET` together; without them, there is no remote heartbeat and the coordinator eventually marks the edge report stale and denies new ICE credentials. If a scrape or POST fails, the process keeps sampling and retrying; its local health changes to `unknown` and `allowNew:false`. Repeated identical failures are logged once until recovery. The report TTL must exceed the sample interval by at least five seconds; the example uses a 5-second interval and 15-second TTL. The body carries a new sample timestamp each cycle, and the coordinator rejects stale or replayed signatures. The endpoint omits host names, interface names, raw coturn output, and secrets.

For a Mac, `edge-turn/com.sameend.edge-turn-agent.plist.example` is a launchd supervision template. `edge-turn/edge-turn-agent.service.example` remains a Linux alternative. Adapt and review the applicable template on the selected host. Configure automatic restart after process failure and monitor both service state and coordinator health. Protect the environment file, which contains the health-signing secret: owner-only mode `0600` for a user LaunchAgent, or root-owned and readable only by the service group for the Linux example, such as mode `0640`. Keep the host agent health endpoint and coturn Prometheus exporter on loopback/private access. Do not treat an active process or locally sampled `healthy` estimate alone as a healthy cloud report.

CPU load uses Node CPU counters on supported hosts. Linux reads `MemAvailable` from `/proc/meminfo` and samples aggregate outbound bytes from `/proc/net/dev`; stacked interfaces can double-count traffic, making that estimate conservative. On macOS, memory uses the bounded `/usr/bin/memory_pressure -Q` system-wide free-percentage output as a pressure proxy. Network sampling obtains the default route with `route -n get default`, verifies that the route is a hardware `en` interface through `networksetup -listallhardwareports`, then reads only its `<Link#...>` row using `netstat -ibn -I <interface> -f link`. It ignores duplicate IPv4/IPv6 rows, virtual `utun`/bridge/loopback routes, mismatched explicit `networkInterface` values, and ambiguous counters. If any command/parser is unsupported or times out, the reading is unknown. A configured `networkInterface` may pin the expected physical default interface; if the route changes away from it, rate becomes unknown until configuration is reviewed. The MAC outbound counter includes all traffic on that physical interface, not only TURN, and does not estimate VPN inner traffic when the default route is a tunnel. The first CPU and network samples are unknown because a rate needs a prior sample. It does not run speed tests. Coturn metrics are fetched from the configured local URL with a 1.2 second timeout.

## Operator limits and overload behavior

Set `uplinkBudgetMbps` from an administrator measured or provider declared sustained egress capacity. The monitor constrains new admission at `uplinkBudgetMbps * uplinkHeadroomRatio` (80% by default) using the sampled current outbound rate. No active speed test is run. This rate is host-wide interface accounting. Linux aggregates non-loopback counters and can overcount stacked interfaces; macOS samples only the verified physical default interface. Unknown readings fail closed. Set `allocationLimit` to the configured total coturn allocation quota. New admission becomes constrained at its configured headroom (90% by default), while coturn `total-quota` and `user-quota` remain the server-side allocation limits. CPU busy at or above 90% and available memory at or below 10% also constrain new admission. Tune these thresholds only after the selected host has been measured under representative TURN traffic.

When reports become unknown, constrained, or stale, the coordinator withholds new edge ICE credentials. Direct peer reservations remain independent. This does not instantly revoke already-issued credentials, cancel authenticated allocations, or disconnect sessions. Short credential TTLs narrow the admission window; coturn allocation quotas and `bps-capacity` / `max-bps` are needed to cap allocations and bandwidth at the server. A static quota is the actual overload safety boundary while an issued credential remains usable.

## Coturn configuration boundary

`edge-turn/turnserver.conf.example` lists preparation directives only. It leaves ports, TLS files, and limits commented out, and includes no real domain or secret. Do not start coturn from this template: omitted allocation quotas are not configured, and coturn's default quota value is unlimited. On the designated host, the operator must set a real `total-quota` exactly equal to cloud `EdgeTurnAllocationLimit` / agent `allocationLimit`, choose a positive `user-quota`, and configure appropriate `max-bps` and `bps-capacity` limits. Review the rendered coturn configuration and confirm the running server applied those values before enabling cloud TURN. The monitor cannot inspect coturn's configuration or prove those quotas match its declared limit. These coturn settings are the server-side enforcement boundary for valid credentials that remain usable. The policy monitor is an admission signal; it does not dynamically rewrite coturn limits or terminate sessions.

When available, the monitor reads coturn's named `turn_total_allocations{type="..."}` gauge. It sums that exact gauge across types and does not guess other metric names. If coturn metrics are disabled/unavailable or the gauge is absent, allocation capacity is unknown, so new admission is denied. Current coturn documentation says Prometheus can be enabled with `--prometheus` and defaults to port 9641; bind the exporter to loopback or otherwise restrict access. See the [coturn Prometheus documentation](https://github.com/coturn/coturn/blob/master/docs/Prometheus.md), [coturn metrics source](https://github.com/coturn/coturn/blob/master/src/apps/relay/prom_server.c), and [coturn server options](https://github.com/coturn/coturn/wiki/turnserver) for the metric and quota/bandwidth semantics.

## Mac prerequisite supervisor

`mac-supervisor.mjs` maintains only explicitly configured UPnP mappings, each with a one-hour lease. The configured local IPv4 must still belong to a non-internal interface on this Mac. It refuses mappings owned by another service, checks the router's external IPv4 against the configured address, verifies the certificate and its matching key, and checks the live loopback TLS listener with public CA validation, the IP identity and the expected leaf. Router timeouts and unverifiable state are unhealthy; an IP change does not change cloud configuration. This check is separate from capacity measurements and does not establish external reachability.

Inventory is complete only when `GetGenericPortMappingEntry` returns the UPnP 713 out-of-bounds fault. Other faults, including 601, do not establish an empty table: a fault during the initial inventory blocks mapping writes, and a fault during final verification leaves the batch unhealthy. See the [WANIPConnection:1 specification](https://upnp.org/specs/gw/UPnP-gw-WANIPConnection-v1-Service.pdf) (§2.4.14) and [UPnP Device Architecture 1.0](https://www.upnp.org/specs/arch/UPnP-arch-DeviceArchitecture-v1.0-20080424.pdf) (action error codes).

The mapping batch reads one bounded inventory before any writes and checks ownership for the entire requested set. It leaves enabled rules with at least 900 seconds remaining alone, renews only missing, disabled or near-expiry rules, then verifies a final inventory. Missing, malformed, static (zero) or insufficient leases cannot establish a healthy temporary route. The 900-second minimum exceeds the 600-second health-status lifetime. SOAP requests are serialized and spaced by at least 100 milliseconds. In the regression fixtures, 19 fresh rules require 40 reads and no writes; renewing 19 near-expiry rules takes 59 requests. This avoids repeated full scans and unnecessary renewal writes. A failed batch can leave some owned rules renewed; it does not report success or attempt to remove unrelated rules. UPnP provides no conditional write, so another controller changing a rule between the inventory and write remains a cross-process race. Inventory size, response bytes, timeouts and mapping count are bounded.

Create a private, mode `0600` JSON file with absolute paths (examples are placeholders):

```json
{
  "router": {"controlUrl":"http://192.168.1.1/control", "gatewayAddress":"192.168.1.1", "localAddress":"192.168.1.2"},
  "expectedPublicIPv4":"203.0.113.1",
  "mappings":[{"protocol":"UDP","external":3478,"internal":3478}],
  "certPath":"/private/edge/tls/cert.pem", "keyPath":"/private/edge/tls/key.pem",
  "acmePath":"/private/edge/acme", "legoPath":"/private/edge/runtime/bin/lego",
  "coturnPidFile":"/private/edge/coturn.pid", "tlsPort":5349,
  "statusPath":"/private/edge/supervisor-status.json", "intervalMs":120000
}
```

List every required UDP and TCP listener and relay mapping explicitly, including individual relay ports; port 80 is reserved for the temporary HTTP-01 challenge mapping to local port 8080. Renewal is attempted only within 48 hours of expiry. The configured lego must support the short-lived IP profile and the existing account; the supervisor runs the specified HTTP-01 issuance command, verifies the resulting IP certificate and key, replaces the protected runtime files, sends coturn `SIGUSR2`, and checks the live leaf. It never uses `SIGUSR1`, which drains and stops this coturn version. A protected pending marker makes installation and reload resumable: after an interruption or failed reload, the next cycle validates the ACME pair, reissues it if it has expired or is within 48 hours of expiry, replaces both runtime files again, retries SIGUSR2 and TLS verification, and removes any owned challenge mapping before clearing the marker. Failure to renew, remove the owned challenge mapping, reload, or verify TLS leaves health unknown; an unremoved mapping is limited by its one-hour lease. Protect the ACME account, key, configuration, and status directory from modification by other users.

Set `supervisorStatusPath` in the capacity agent config to the same absolute status path. Missing, malformed, future-dated, expired, or unhealthy status sets the sample's `metricError` and prevents healthy admission; omit the setting only on legacy hosts without this prerequisite. The status expires after ten minutes and is marked unhealthy while a cycle runs. A supervisor failure cannot bypass the capacity policy, and capacity failures cannot be made healthy by the supervisor.

For a user LaunchAgent, copy the reviewed modules (including their imports) to a stable private runtime directory, substitute absolute executable, module, config and log paths in `com.sameend.edge-turn-supervisor.plist.example`, and place the resulting plist in the operator's `~/Library/LaunchAgents`. Run the agent and coturn as the same regular user so the supervisor can signal the coturn PID; no root account is required. Review ownership, permissions, paths, network and firewall prerequisites before loading it. A loaded job is not proof that the supervisor is healthy or that external TURN works.

## Operator-static preparation (not enabled by default)

The explicit `forwardingMode: "operator-static"` supervisor mode is for reviewed, operator-maintained forwarding rules. It never creates, renews or deletes router mappings. The operator must maintain the rules and an owner-only manifest; the manifest is an assertion, not an inventory of other router rules. The supervisor continues checking the assigned local address, the router-reported public address, the certificate and key, and the CA-verified local TLS leaf. It then performs a bounded public-address TURN/TLS proof with two short-lived authenticated allocations and two nonce-checked data directions. The probe checks the allocated public addresses and ports against the manifest. This proves only the two allocated relay ports at the time and from the host's public-address route, which may use NAT hairpinning; it does not prove off-network reachability or every relay port. Health still requires the existing capacity agent and coordinator acknowledgement.

The supervisor config additionally supplies an absolute `staticManifestPath` and `staticManifestSha256`. The manifest must be a regular file owned by the service user with no group/other permissions. Its version-1 JSON contains `localIPv4`, `publicIPv4`, the exact `mappings` array, `tlsExternalPort`, `relayMin`, `relayMax`, and an absolute `secretPath` to an owner-only file containing the TURN REST secret. The SHA-256 is the lowercase hex digest of UTF-8 `canonicalStaticManifest(manifest)` exported by `mac-supervisor.mjs`; its canonical form sorts the mapping set. The public TLS port must map to the configured supervisor `tlsPort`, every UDP relay-pool port must map unchanged, and TCP 80 is excluded. The existing UPnP mode remains the default.

Static renewal is intentionally **not automated** in this slice. A certificate at or within 48 hours of expiry, or an interrupted renewal marker, makes health unknown until the operator completes a separately reviewed renewal and removes the pending condition safely. No port-80 mapping or TLS-ALPN proxy is installed by this mode. Stale supervisor status, failed external proof, missing metrics, or failed coordinator acknowledgement also deny new credentials. A same-LAN physical Mac-to-Windows forced-relay picture trial and a public-address authenticated nonce data check have passed; neither establishes off-network reachability or unattended renewal. Admission may be enabled only after the current full supervisor cycle succeeds, the certificate has more than 48 hours remaining with no pending marker, and the coordinator acknowledges healthy capacity. A reviewed renewal procedure remains separate work; the 48-hour and pending-marker checks continue to fail closed.

For a standalone public-path diagnostic, `edge-turn/public-turn-check.mjs --config <private-file>` accepts owner-only JSON with `host`, `port`, `fingerprint`, `relayMin`, `relayMax`, and `secretPath`. It prints only an allowlisted stage and aggregate coverage; it never prints the secret or addresses. It attempts to release every allocation whose authenticated request was sent and closes both sockets; if the network fails, remote cleanup cannot be guaranteed, and health remains failed. This diagnostic itself does not authorize admission.
