# Fans’ corner pilot contract

Implementation scope agreed 25 October 2026: shared opt-in text forum, persistent operator feedback, small published waiting-content pack, and staff management. Private room secrets/chat and P2P match delivery are separate. No audio/video or real advertisements are included in this release.

All endpoints are under `/v1/community`, JSON over the existing API base. Email/password fan accounts use a separate Cognito pool and are independent of staff accounts and all club invitations. Public forum reading and starting/joining private rooms do not require a fan account. Forum participation requires account sign-in, rules acceptance and a separate pilot code. Display names are self-chosen. No private-room identifiers, invitations or chat are sent to the account system. Private feedback also remains available without account signup through a browser-local identity.

## Browser and API contract

- `GET /config` → `{forumEnabled,categories:[{id,label}],adminAuth:{issuer,clientId,domain,redirectUri},fanAuth:{issuer,clientId,domain,redirectUri,scope:'sameend-community/use'},retentionDays:365}`. Categories: `general`, `club`, `match`, `ideas`. Configuration contains public app identifiers only.
- `POST /identities` `{id,tokenHash,name}` → `{id,name,forumMember:false}`. Browser secrets are 32 random bytes in canonical base64url (43 characters); registration sends only the SHA-256 hash and is idempotent only for the same identity/credential. `GET /me` with the browser bearer returns its profile. These legacy credentials authorize private feedback only; all old forum participation endpoints return 401 `account_required`, including for previously enrolled browser identities.
- `POST /member/identity` account access token, `{name?:string,legacyToken?:string}` → profile `{id,name,forumMember,status,blockedMemberIds,version}`. Creates a stable fan identity or returns the account's existing one. A supplied browser secret claims its existing fan ID and private feedback in one transaction, preserves membership/suspension/blocks/counts, and consumes the old credential. No email/name matching establishes ownership. A consumed secret can be retried only by the same account; another account or an attempted second identity merge receives 409. Without the original secret, previous browser ownership cannot be recovered automatically. `GET /member/me` returns the bound profile; before bootstrap it returns 401 `account_profile_required`.
- `POST /member/membership` account access token, `{code,agree:true,name?:string}` → member profile. An explicit display name may be chosen at first forum joining while retaining the existing feedback identity. Membership can be disabled in settings. Codes are hashed by the service, never returned or logged. Staff set/rotate the code through management.
- `GET /feedback` browser bearer, or `GET /member/feedback` account access token → `{items}` for this fan only. The corresponding `POST` accepts `{id,kind:'problem'|'suggestion'|'worked',title,text,contact?:string,diagnostics?:{build,role,roomState,playbackMode,sourceEnded,online,reserveSeconds}}` → feedback record `{id,ownerId,version,kind,title,text,status:'received',response:'',createdAt,updatedAt}`. Contact and diagnostics stay private to sender/support. No arbitrary diagnostics. Reusing an id is idempotent within this identity. States: `received`, `investigating`, `answered`, `fixed`. Account feedback remains available without pilot membership and during forum suspension. A claimed browser credential no longer reads its former receipts; the owning account reads them through `/member/feedback`.
- `GET /threads?category=all|general|club|match|ideas&sort=hot|new|top&cursor=...` → `{items,cursor,total,latest}`. No bearer is required while the forum is enabled (403 `forum_closed` otherwise). These routes always return a guest view and ignore optional credentials. `GET /member/threads` and `GET /member/threads/:id` require a verified account access token and add personal votes/block filtering, without requiring pilot membership. Items expose `{id,category,title,excerpt,authorId,authorName,spoiler,locked,createdAt,updatedAt,replyCount,score,myVote}`. Without `sort`, the original sort-key paging is kept for staff tools. Hidden/deleted content is not returned.
- `POST /member/threads` account access token plus active membership, `{id,category,title,text,spoiler:boolean}` → thread record. `GET /threads/:id` (public read as above) → `{thread,replies,cursor:null}` with the whole bounded conversation (≤500 replies) in time order; thread and replies add `score,myVote`; replies add `threadId,parentId|null,depth (1–4),replyToName?`. A removed or blocked reply that still has visible replies is returned as an anonymous placeholder (`text:''`, `authorId:null`, `deleted|hidden|blocked:true`). `POST /member/threads/:id/replies` `{id,text,parentId?}` → reply; a parent must be a visible reply in the same thread; replies to depth-4 comments attach to that comment's parent and record `replyToName`.
- `POST /member/votes` account access token plus active membership, `{threadId,postId,value:0|1}` → `{threadId,postId,score,myVote}`. One like per fan per post, idempotent and reversible. Tallies are separate records, so likes never change post versions. Votes have their own 120/minute per-fan allowance. Match category forces spoiler protection. Posts must use safe text rendering.
- `POST /member/reports` account access token plus active membership, `{id,threadId,postId,reason}` → `{id,status:'open'}`. `POST /member/posts/delete` `{threadId,postId,expectedVersion}` deletes only own post. `POST /member/blocks` `{memberId,blocked:boolean}` → profile; blocked authors are omitted from member reads.
- `GET /content` unauthenticated → `{revision,items}`. Published and currently scheduled items only; complete JSON pack ≤50 KB. Items: `{id,type:'story'|'quiz'|'ad',title,body,question?,choices?:string[],answerIndex?,explanation?,sponsor?,url?}`. No arbitrary HTML, remote images, media, scripts or trackers. HTTPS links only, no invitation fragments. Local evergreen fallback remains available.

## Fan account security and retention

Production `/v1/community/member` and `/v1/community/member/*` routes require a separate API Gateway JWT authorizer with the fan pool issuer/client and `sameend-community/use` scope. Lambda accepts only gateway-provided claims matching the configured fan issuer, `client_id`, `token_use:'access'`, bounded `sub`, expiry, optional `nbf`/`iat`, and exact scope. Fan ID tokens, staff tokens, unverified JWT payloads and browser secrets cannot authorize member routes. The backend also enforces this boundary behind the unauthenticated catch-all route. There is no production mock-authorizer or local fan-token bypass.

`ACCOUNT#sha256(issuer/sub)` and the reverse-bound `FAN#id` have no DynamoDB TTL. They retain a stable ownership mapping and suspension/identity metadata across the existing 365-day content and receipt lifetime. Only those bound FAN profiles are active without an expiry; ordinary content, receipts, votes and legacy credentials still expire on reads. Missing or mismatched bound profiles fail closed rather than creating a replacement ownership mapping. Linking never changes content/receipt expiry. Claim hashes are private retry metadata and are not bearer credentials.

Account sign-in uses authorization code + S256 PKCE and a separate callback window so an active private room is never navigated away from. Any opener handoff validates origin, expected window source and a one-use nonce. Sign-out clears account tokens, personal results and pending response applicability; forum actions never fall back to a browser secret. Browser feedback can create a fresh independent unsigned receipt identity. Cognito token revocation alone does not instantly invalidate JWTs already accepted by signature/expiry validation; short access-token lifetimes and server-checked profile suspension bound that behavior.

## Staff contract

Production routes `/v1/community/admin/*` require API Gateway verified Cognito JWT claims. Use an ID token obtained through hosted sign-in, authorization code + PKCE and MFA; role groups are `sameend-admin`, `sameend-support`, `sameend-moderator`, `sameend-editor`. Admin covers all. The backend must validate issuer/audience/group on the gateway claims, never a user-supplied role/header. Local loopback review can inject an explicit local admin credential hash; this is never enabled in Lambda. No staff bearer token is saved to localStorage or placed in URLs. PKCE state/verifier may live transiently in sessionStorage and are removed after exchange.

- `GET /admin/feedback` → `{items,cursor}`; `POST /admin/feedback/:id` `{status,response}` → record. Support/admin only.
- `GET /admin/threads?category=...&cursor=...` and `GET /admin/threads/:id` → same thread shapes, including hidden content for moderation. Moderator/admin only.
- `POST /admin/threads` `{id,category,title,text,spoiler}` → thread `{…,staff:true,created}`. Moderator/admin only; audited as `thread.publish`. Publishes a discussion as the labelled “Same End team” (`authorId:'same-end-team'`). Republishing the same ID returns the existing team thread (`created:false`); an ID already used by a fan returns 409. Fans can read, like, reply to and report team threads, but cannot delete or block them.
- `POST /admin/moderation` `{threadId,postId,action:'hide'|'restore'|'lock'|'unlock',reason}` → `{ok:true}`. Moderator/admin only. No restore of author-deleted text.
- `GET /admin/reports` → `{items,cursor}`; `POST /admin/reports/:id` `{status:'open'|'resolved',note}` → record. `POST /admin/members/:id` `{status:'active'|'suspended'}`. Moderator/admin only.
- `GET /admin/content` → `{items,revision}`; `POST /admin/content` complete bounded item `{id,type,title,body,question?,choices?,answerIndex?,explanation?,sponsor?,url?,published:boolean,startsAt?:epochMilliseconds,endsAt?:epochMilliseconds}` → item. `DELETE /admin/content/:id` → `{ok:true}`. Editor/admin only.
- `GET /admin/settings` → `{forumEnabled,hasJoinCode,requireReview?}`; `POST /admin/settings` `{forumEnabled,joinCode?:string}` → safe settings. Admin only. No join code is returned. Forum is disabled until a code is configured.
- `GET /admin/audit` → `{items,cursor}`. Admin only. Audit records contain actor opaque ID, action, target, time and bounded moderation reason; never credentials, private room material, feedback body or contact data.

All list reads bounded and paginated; stale/conflicting writes must not overwrite unrelated updates. Administrative changes and audit records commit together. Registration/post/report/feedback requests have per-identity/IP/global bounds; request size 16 KB, safe limits for fields, no raw IP persistence. Staff and fan permissions are distinct. Public reads never expose token hashes, contacts, diagnostics or moderation notes. Expiry and deletion are enforced on reads, not just asynchronous TTL. Local durable storage exists solely for isolated development and must never replace DynamoDB in deployment.

Concurrency amendment: mutable records expose `version`. Staff update bodies and author deletion include `expectedVersion`, returning409 rather than silently replacing a changed record. New content/settings creation uses expectedVersion0; existing records use their returned version. Moderation hide/restore uses post version; lock/unlock uses thread version. Member suspension may use a fresh GET `/admin/members/:id` to obtain version first.

## Integration ownership

- API worker owns `backend/community-api.mjs`, `backend/test/community.test.mjs`; exports `createCommunityApi({store,now,allowedOrigins,adminAuth,fanAuth,localAdminTokenHash})` with `.handler(event)`. Lambda dispatch passes `COMMUNITY_FAN_ISSUER`, `COMMUNITY_FAN_CLIENT_ID`, `COMMUNITY_FAN_DOMAIN`, `COMMUNITY_FAN_REDIRECT_URI` and `COMMUNITY_FAN_SCOPE`.
- Fan UI worker owns `community.js`, `community.css`; inserts UI after `#magnet-panel` at runtime and persistent header/footer access, without editing app.html/build-pwa. Reads `window.SameEndConfig.apiBase`; localhost uses `/api`. Export `window.SameEndCommunity={open,feedback,refresh}`. No auto forum loading/polling.
- Staff worker owns `manage.html`, `manage.js`, `manage.css`, `backend/community-infrastructure.mjs`, `backend/test/community-infrastructure.test.mjs`, `docs/community-management.md`. Infrastructure function merges into current template; root integrates it. Staff HTML contains build-time `__SAME_END_CONFIG__` JSON placeholder.
- Root owns buffering screen modules, build/app/serve and backend dispatch integration, local durable runner and end-to-end browser verification. All operate in the same isolated worktree without modifying another worker’s files.
