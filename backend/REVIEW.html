Review and run

From the same-end/backend folder: npm ci, then npm test. npm start runs the local API on 127.0.0.1:8795 with temporary memory storage and push disabled unless real VAPID environment values are provided. The app server should proxy /api/v1/… to /v1/….

node deploy.mjs --prepare-only prepares a private archive without AWS writes. After review, the owning task can run node deploy.mjs using its existing AWS credentials. The default region is eu-west-1, and only dedicated same-end-social-… stack names are accepted. Standard output includes the public API origin and stack status. Private state is saved at work/same-end-social/deployment.json, two folders above this backend.

The new CloudFormation resources are a private deployment-artifact bucket; an HTTP API; one Lambda function; one DynamoDB table with a reminder index and TTL; a seven-day log group; a minute reminder rule; and IAM permissions for this function's own table, index and logs. Public CORS permits only https://www.sameend.com. The private VAPID key is a NoEcho deployment parameter and Lambda environment value; never copy deployment state into a public build.

Delivery semantics and privacy

A successful push means its provider accepted it. It does not prove a device displayed a notification. Persistent per-device/event receipts prevent repeat sends during normal repeated or concurrent scheduler runs. A process crash after provider acceptance but before saving its receipt can still produce a duplicate on retry; exactly-once external delivery cannot be guaranteed. Transient failures retry with bounded backoff; expired registrations are removed on 404/410. Disabled push returns an explicit unavailable response.

Notifications contain the club ID, optional opaque event ID and a generic local-saved-club URL. They never contain club invitation keys, chat, team names, match details or a stream address. Browser endpoints are restricted to supported HTTPS push-provider hosts, valid elliptic-curve keys and bounded lengths. Redirects are not followed. API responses and logs omit capabilities, subscription details and provider errors.

Timestamp metadata, random club/event IDs, capability hashes and subscription endpoints remain server-visible. Anyone holding a read capability can read and post encrypted club chat and manage a reminder registration in that club. Owner changes require the separate owner capability. Self-chosen display names remain unverified identities.
